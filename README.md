# GAMCS HR

An HRMS for Indian and Middle East SMBs, built on **[Frappe HR](https://github.com/frappe/hrms)** and **[ERPNext](https://github.com/frappe/erpnext)**. This repo is the custom Frappe app **`gamcs_hr`**. Every feature we add on top of upstream lives here: the employee lifecycle, attendance, leave, payroll and statutory compliance extensions, plus a richer employee self-service experience.

License: **GPL-3.0** (see [LICENSE](LICENSE)), because the app builds on GPL-3.0 apps (ERPNext, Frappe HR, India Compliance).

## Features

**Available now** (upstream Frappe HR v16 + ERPNext v16 + India Compliance, configured through this app):

- Employee master, org structure, branches, departments, designations and reporting managers
- Holiday lists, leave types, leave policies, leave allocation and leave applications with approvals
- Shift types, shift assignment, and employee check-in with geolocation
- Attendance, including auto-attendance from check-ins
- Payroll: salary components, structures and slips; Indian statutory components (PF, ESI, PT); income tax slabs
- Expense claims, advances, appraisals, recruitment, onboarding and exit
- Frappe HR mobile-friendly self-service PWA at `/hrms`
- Demo data seeder (`gamcs_hr.seed.demo`)

**Planned:** the feature gaps we intend to close are tracked in [docs/build-queue.md](docs/build-queue.md).

## Architecture

```
frappe (framework, MIT)
 └─ erpnext (GPL-3.0)
     ├─ hrms (Frappe HR, GPL-3.0)
     ├─ india_compliance (GPL-3.0)
     └─ gamcs_hr (this repo, GPL-3.0)
```

- The upstream apps are **untouched**. They are cloned at pinned `version-16` branches into a bench outside this repo.
- Every customisation lives in `gamcs_hr`. We extend upstream through hooks (each feature module has its own `hooks_part.py`, merged by `hooks.py`), through custom fields and property setters declared per module in `setup.py`, through extension classes with pluggable validators, through our own doctypes, and through our own pages. See [docs/conventions.md](docs/conventions.md).
- Version choice and its rationale: [docs/decisions/0001-frappe-v16-stack.md](docs/decisions/0001-frappe-v16-stack.md).

## Prerequisites

- Docker Desktop (8 GB RAM allocated is enough; give it 10 GB or more of free disk for the first build)
- macOS or Linux with bash and git
- Nothing else on the host. Python 3.14, Node 24 and bench all run inside the `frappe/bench` container.

## Quick start

```bash
git clone https://github.com/Prakhartomarr/hrms-.git ~/hrms
cd ~/hrms
infra/dev/setup.sh          # first run: creates .env, ~/hrms-bench, starts containers
infra/dev/hr.sh logs        # follow the first-time install (about 15 to 30 minutes)
```

The first run clones frappe, erpnext, hrms and india_compliance (all `version-16`) into **`~/hrms-bench`**, mounts this repo at `~/hrms-bench/apps/gamcs_hr` (so edits are live), builds assets, creates the site `hr.localhost`, and installs every app on it. Later runs skip whatever already exists.

| What | URL |
| --- | --- |
| Desk | http://hr.localhost:8200/app (v16 redirects to `/desk`) |
| Frappe HR self-service | http://hr.localhost:8200/hrms |
| Login | http://hr.localhost:8200/login |

- **Ports:** web `8200`, socketio `9200`. The Docker compose project is `hrms-dev`.
- **Login:** user `Administrator`. The dev password is `ADMIN_PASSWORD` in **`~/hrms/.env`**, which is gitignored and generated by `setup.sh`. It is never committed.
- `*.localhost` resolves to 127.0.0.1 in browsers and curl, so no `/etc/hosts` change is needed.

### Day-to-day commands

```bash
infra/dev/hr.sh up          # start
infra/dev/hr.sh down        # stop (keeps data)
infra/dev/hr.sh logs        # follow bench output
infra/dev/hr.sh bench <args>  # run any bench command in the container
infra/dev/hr.sh shell       # bash inside the bench container
infra/dev/hr.sh migrate     # bench migrate on hr.localhost
infra/dev/hr.sh build       # rebuild assets
infra/dev/hr.sh seed        # (re)load demo data, idempotent
infra/dev/hr.sh test        # run gamcs_hr tests on hrtest.localhost
infra/dev/hr.sh reset       # drop and recreate the site (keeps the bench; asks first)
infra/dev/hr.sh nuke        # remove containers, volumes and ~/hrms-bench (asks first)
```

## Seed data

`infra/dev/hr.sh seed` runs `bench --site hr.localhost execute gamcs_hr.seed.demo.run`. It is idempotent, so it is safe to re-run. It creates:

- Company **Demo Pvt Ltd** (India, INR, FY Apr to Mar) with branches Bengaluru and Mumbai, plus departments
- Holiday list "Demo India 2026-27" (Jan 2026 to Mar 2027: Sundays plus national holidays), assigned to the company via a v16 Holiday List Assignment
- Fiscal year and Payroll Period FY 2026-27 (Apr to Mar)
- 50 employees (`DPL001` to `DPL050`) with a reporting hierarchy: a CEO, 6 department heads reporting to the CEO, and team members reporting to their head. Heads are the leave approvers for their departments.
- Leave types (Casual, Sick, Privilege, Leave Without Pay) and a leave policy, assigned to everyone
- Shift types General (09:30 to 18:30) and Early (07:00 to 16:00) with auto-attendance and late-entry marking. Each office has a Shift Location with a 200 m check-in radius; every employee has a shift assignment tied to their branch's location; and geolocation tracking plus mobile check-in are enabled in HR Settings.
- Salary components Basic (50% of gross), HRA (20%), Special Allowance (30%), PF (12% of basic, capped at the ₹15,000 wage ceiling), ESI (0.75% while gross is ₹21,000 or less), Professional Tax (₹200 when gross is ₹25,000 or more, Karnataka-style) and Income Tax (TDS). A submitted structure "Demo India Monthly" is assigned to every employee.
- Income tax slab for FY 2026-27 (new regime): standard deduction ₹75,000, nil tax up to ₹12,00,000 taxable income (87A relief), and 4% cess
- No historical salary slips. hrms projects TDS only over the months still to be paid, so the first slip you run mid-year shows a lower TDS than a full-year figure would.
- Desk + `/hrms` logins for the six department heads (for example `simran.mukherjee.038@demo.example`, the HR manager). Their password is `DEMO_PASSWORD` from `.env`, falling back to `ADMIN_PASSWORD`. Administrator is not an employee, so `/hrms` shows "invalid employee" for it. Log in as a department head to try the employee app.

## Running tests

Tests run on a separate throwaway site, **`hrtest.localhost`**, so upstream fixtures (`_Test Company` and so on) never pollute the demo site. The test site has frappe, erpnext, hrms and gamcs_hr, but **not india_compliance**: ERPNext's test fixtures fail its GST validation, and upstream hrms CI also runs without it.

```bash
infra/dev/hr.sh test-site                    # once: (re)create hrtest.localhost, allow_tests on
infra/dev/hr.sh test                         # gamcs_hr tests (exact-value payroll checks)
infra/dev/hr.sh upstream-test hrms.hr.doctype.leave_application.test_leave_application
```

Baseline upstream results are recorded in [docs/baseline-tests.md](docs/baseline-tests.md).
